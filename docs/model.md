# 模型与指标

本文只解释模型与指标。公共环境及实验后处理操作见 `setup.md`，各版本训练命令见对应 `version_notes.md`，创建版本与修改代码的位置见 `development.md`。

## 1. 各组件是什么

| 组件 | 作用 |
|---|---|
| MMSegmentation 1.2.2 | 训练、数据加载、评测和推理框架，不是某一个模型 |
| ConvNeXt-B / ConvNeXt-L | 主干网络，从输入图像提取四级多尺度特征 |
| UPerNet / UPerHead | UPerNet的核心解码头，通过上下文池化与多尺度融合完成像素分类 |
| Mask2Former | 多尺度像素解码、掩码约束区域查询，以及区域类别和掩码预测；用于M0与MP |
| 多原型区域语义模块P | 训练标签约束的8类×4个EMA原型，引导当前图像的区域特征聚合和残差增强；用于UP与MP |
| FCNHead | 训练期辅助监督头，最终预测使用主解码头 |
| ImageNet-21K分类预训练 | 初始化主干，不包含针对赛事训练好的分割能力 |

当前使用公开分类预训练，不加载外部语义分割或检测checkpoint。本轮结构候选都使用ConvNeXt-B；L只是后续候选，不能预设L一定更好。三个结构版本已实现并完成本地运行检查，尚无正式训练、完整验证或平台成绩。

## 2. 数据如何经过模型

原始基线、v0和U0控制采用以下流程：

```text
RGB图像
  -> 归一化及训练增强
  -> ConvNeXt四级特征
  -> UPerHead融合
  -> 8个有效类别的像素logits
  -> argmax得到内部编号0..7
  -> 推理导出恢复官方编号1..8
```

本轮结构版本分别为：

| 版本 | 主干之后的路径 | 训练监督 |
|---|---|---|
| M0 | 多尺度像素解码 → 区域查询 → 类别与掩码组合成8类语义分数 | 原生查询CE、mask BCE、Dice及中间层监督 |
| UP | UPer融合 → P与UPer适配器 → 8类像素logits | 保留U0的CE/RMI及FCN辅助监督，无新增loss |
| MP | M0像素解码 → 同一个P → 增强mask features及三层query memory → 原区域查询预测 | 保留M0监督，无新增loss |

P原型是checkpoint中的统计buffer，只在训练loss计算后用官方训练标签更新；当前预测使用更新前的原型，验证和测试不读取GT、不更新原型。UP与MP的P核心相同，接入适配器不同；类别或原型缺席不会伪造有效槽。当前统计实现只支持单GPU，物理batch改变还须核对每micro batch的EMA更新频率。机制、超参数、预算和检查证据分别以各版本`version_notes.md`与冻结清单为准。

M0与U0同时改变分割头及其配套监督，不能将未来收益完全归因于结构；UP与U0、MP与M0比较P的增量效果。最终仍按固定验证集整体mIoU选择单模型，目前没有胜出结论。

官方标签虽有9个ID，但ID 0是Ignore，不是有效预测类。加载mask时官方0转为255，官方1..8转为内部0..7；损失与评测排除255。真实Ignore像素不参与交集或并集。

每次验证先累计整个验证集各类交集和并集，再计算IoU和8类mIoU，不是简单平均每张图的mIoU。验证由训练程序执行，分析工具只读取已写入日志的指标。

## 3. 解释训练结果

- 训练loss和训练Acc反映优化情况，不等于验证精度。
- 最佳验证mIoU适合辅助选权重，但不能独自代表整个配置的表现。
- 单模型报告以末段窗口代表mIoU、最终值、波动和每类IoU描述总体情况；AUC是训练过程表现，不是最终测试精度。
- 窗口趋势与“基本收敛”等标签是启发式提示，不是统计显著性结论。固定验证集上的多次调参仍可能过拟合。
- 跨主干比较不能只对齐iter，要关注样本曝光量、优化器更新次数和评测方式。
- 具体数据定义与原始统计见 `data_spec.md`；单模型分析及实验比较的调用见 `setup.md`。
