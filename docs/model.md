# 模型与指标

本文只解释模型与指标。公共环境及实验后处理操作见 `setup.md`，各版本训练命令见对应 `version_notes.md`，创建版本与修改代码的位置见 `development.md`。

## 1. 各组件是什么

| 组件 | 作用 |
|---|---|
| MMSegmentation 1.2.2 | 训练、数据加载、评测和推理框架，不是某一个模型 |
| ConvNeXt-B / ConvNeXt-L | 主干网络，从输入图像提取四级多尺度特征 |
| UPerNet / UPerHead | UPerNet的核心解码头，通过上下文池化与多尺度融合完成像素分类 |
| FCNHead | 训练期辅助监督头，最终预测使用主解码头 |
| ImageNet-21K分类预训练 | 初始化主干，不包含针对赛事训练好的分割能力 |

当前使用公开分类预训练，不加载外部语义分割checkpoint。B用于开发消融，L只是后续候选，不能预设L一定更好。

## 2. 数据如何经过模型

```text
RGB图像
  -> 归一化及训练增强
  -> ConvNeXt四级特征
  -> UPerHead融合
  -> 8个有效类别的像素logits
  -> argmax得到内部编号0..7
  -> 推理导出恢复官方编号1..8
```

官方标签虽有9个ID，但ID 0是Ignore，不是有效预测类。加载mask时官方0转为255，官方1..8转为内部0..7；损失与评测排除255。真实Ignore像素不参与交集或并集。

每次验证先累计整个验证集各类交集和并集，再计算IoU和8类mIoU，不是简单平均每张图的mIoU。验证由训练程序执行，分析工具只读取已写入日志的指标。

## 3. 解释训练结果

- 训练loss和训练Acc反映优化情况，不等于验证精度。
- 最佳验证mIoU适合辅助选权重，但不能独自代表整个配置的表现。
- 单模型报告以末段窗口代表mIoU、最终值、波动和每类IoU描述总体情况；AUC是训练过程表现，不是最终测试精度。
- 窗口趋势与“基本收敛”等标签是启发式提示，不是统计显著性结论。固定验证集上的多次调参仍可能过拟合。
- 跨主干比较不能只对齐iter，要关注样本曝光量、优化器更新次数和评测方式。
- 具体数据定义与原始统计见 `data_spec.md`；单模型分析及实验比较的调用见 `setup.md`。
